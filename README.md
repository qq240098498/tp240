# 冷链温控与批次放行台

冷库与冷藏车的温控值班台：录冷库与探头、登批次、登记监测段（一批货可跨多台探头、多个设备）、盯按时刻接成的温度时间线、算超限与断链（区分交接豁免与真断链）、判放行还是拒收。

## 运行

```
npm install
npm start
```

默认端口 5240（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：冷库与运行中数量、探头数量与已过校准期的探头数、批次总数与各状态条数、温度记录条数与人工记录数、放行与拒收条数、当前满足放行条件的批次数与被挡下的批次数、没有任何温度记录的批次数、真断链总数与交接豁免总数、最高与平均 MKT、按冷库一行给出探头与批次数。
- **冷库与探头**：冷库台账（编码、名称、类型、位置、库位、状态）与探头台账（编号、所属冷库、位置、状态、校准有效期、记录条数），都带增改删。
- **批次**：批次清单（批次号、品名、规格、件数、所在冷库、入库时刻、状态、监测段数、温度记录条数、最长超限、累计超限、MKT、真断链/豁免、放行情况），行内展开**监测段、判定时间线、未采用记录、分段超限段、缺口（真断链/交接豁免）、放行判定（按段定责）**与放行单，并提供「放行」「拒收」「加一段/改段/删段」入口。
- **温度记录**：记录清单（批次、探头、时刻、温度、来源、登记人、是否超限），支持按批次与探头筛选、单条新增与删除。新增时按所选批次只给在册探头，并校验记录时刻落在该探头那一段的时间窗内。
- **放行台账**：放行与拒收记录（批次、决定、时刻、经办人、当时的 MKT、最长超限、累计超限、真断链/豁免、不达标项与责任段、依据），拒收/放行时把“哪一段、谁的设备、哪几条记录导致不过”连同豁免一起快照存档。

## 口径（页面上的说明与数字都要与本段一致）

1. **温度带**：默认 2 到 8 摄氏度（可在设置里改），低于下限或高于上限都算超限。
2. **监测段与时间线拼接**：一批货可关联**多台探头与多个设备**（冷库、冷藏车）。每一段登记「设备 + 在册探头 + 起止时刻 + 交接原因」，判定时把各段记录**按时刻接成一条时间线**。换探头（读数漂移换新）、冷库转冷藏车、再回库，就是在末尾续一段；旧数据没有段时，系统按“设备=批次所在冷库、探头=这批最早记录的探头”自动补一条默认段。
3. **重叠时段取值口径（页面写明）**：同一时刻有多条记录时——① 同一探头同一刻既有自动又有手工更正，**以手工为准**；② 交接时两台探头并行（段窗允许交叠），**以监测段序号靠后的段为准**，即交接后的新探头/新设备接管；③ 停用探头名下的记录、以及不落在任何在册段窗内的记录一律不参与判定。所有落选记录都在批次详情「未采用记录」里逐条列出原因，可审计——交叠绝不重复计两遍。
4. **接缝豁免与真断链**：① 同一段内相邻记录时刻差超过 `chainGapMinutes`（默认 15 分钟）算**真断链**，不可豁免；② 段与段接缝处因换探头/换设备产生的空档，时长不超过 `handoverGraceMinutes`（默认 30 分钟）算**交接空档，按口径豁免并标注原因**（责任段、从哪到哪、多少分钟）；接缝空档**超过宽限仍算真断链**；③ 某一段一条记录都没有算真漏数据，按真断链点名该段。**豁免只认“段与段之间、宽限以内”的接缝，绝不允许用豁免把段内漏数据或超宽限缺口盖掉**；宽限改严，原先豁免的接缝会立刻重新计为真断链。
5. **超限段**：同一段内按时刻逐条判，连续超限的时段算一段，**中间有记录回到范围内就断开**，换段（换设备/探头）也重新起段；每段时长按相邻记录的**实际时刻差**累加，每条肇事记录的 id 都挂在该超限段上。
6. **累计超限**：一个批次从入库到当前，所有超限段（跨各监测段）的时长之和；**跨月不重置**，按批次周期累计。
7. **MKT（平均动力学温度）**：按动力学公式算，写成 `MKT = −Ea / (R × ln((Σ e^(−Ea/(R·T)) ) / n)) − 273.15`（活化能 Ea 取 83144 J/mol、气体常数 R 取 8.314，T 用开尔文，n 为参与判定的记录条数）；**不是把温度取平均**。
8. **放行判定**：单次连续超限不超过 `allowExcursionMinutes`（默认 30 分钟）、累计超限不超过 `allowTotalExcursionMinutes`（默认 120 分钟）、全程没有真断链（合格的交接豁免不计入）、参与判定的探头都在校准有效期内、且至少有一条参与判定的记录。各条同时满足才算满足放行条件；**没有任何温度记录的批次不能放行**。
9. **一段不合格整批不合格，并可定位**：不达标项会指出是**第几监测段、该段是谁的设备（冷库/冷藏车）与哪台探头、哪几条记录（record id）、在什么时段、超了多少/断了多少分钟**；交接豁免单独列示，不混入真断链。
10. **停用与检修中的冷库**：其批次仍然照常记录与判定，但在清单里要标出来。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改，含 handoverGraceMinutes） |
| GET / POST | /api/rooms | 冷库清单（支持 status、type、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/rooms/:id | 详情（含探头与批次）/ 修改 / 删除 |
| GET / POST | /api/probes | 探头清单（支持 roomId、status）/ 新增 |
| PATCH / DELETE | /api/probes/:id | 修改 / 删除 |
| GET / POST | /api/batches | 批次清单（支持 roomId、status、product）/ 新增 |
| GET / PATCH / DELETE | /api/batches/:id | 详情（含监测段 legs、判定时间线 timeline、未采用记录 droppedRecords、分段超限 segmentsByLeg、缺口 chainGaps、放行单）/ 修改 / 删除 |
| GET | /api/batches/:id/release-check | 放行判定（含 legs、每条的分段 culprits、交接 exemptions） |
| GET / POST | /api/batches/:id/legs | 该批监测段清单 / 在末尾续一段（自动把原末段封尾） |
| PATCH / DELETE | /api/batches/:id/legs/:legId | 修改一段（设备/探头/起止/交接原因）/ 删除（只能删末段，且段内无参与判定的记录） |
| POST | /api/batches/:id/decision | 放行或拒收，body `{decision, decider, decidedAt, basis, remark}`，放行单快照含 failed、culprits、exemptions |
| GET / POST | /api/records | 温度记录（支持 batchId、probeId、source、from、to）/ 新增（校验在册探头与段窗） |
| DELETE | /api/records/:id | 删除一条记录 |
| GET | /api/releases | 放行台账（支持 batchId、decision） |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
